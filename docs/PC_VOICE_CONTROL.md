# Windows本地语音控制更新（PC 0.4.1 / 固件沿用0.4.0）

## 已确认的基础与当前范围

用户已在Windows Python3.11/x64成功安装0.4.0依赖和中文模型，用板载MIC1经USB获得连续中文临时/最终结果；短时帧连续增加、队列通常2–3帧，Ctrl+C退出正常。这是用户实际设备证据，不是云端替代测试。不复制其完整对话、录音或串口原始日志到仓库。主观效果认可不等于测得字错率；长时稳定性仍未验收。

本次用户明确同意在这条Windows本地ASR链路上加入唤醒/表情指令。**只更新电脑程序，不修改或重刷已验证固件，不更换模型和依赖。** 仍需Windows运行，不是ESP32独立中文识别；不接LLM/TTS/云服务，不保存录音/转录。不使用模糊匹配把近音名称当唤醒。

## Windows更新步骤

1. Ctrl+C退出当前转录程序，按需在批处理退出提示输入Y；关闭其它COM3程序，包括miniterm。
2. 下载`desktop-nomi-pc-voice-control-v0.4.1.zip`。将ZIP里的 **pc文件夹** 合并复制到 `D:\NOMI-ASR-debug`，覆盖同名程序文件。确认新的`start_control.cmd`位于 `D:\NOMI-ASR-debug\pc`。**保留已有pc\.venv和pc\models，不删除整个pc目录。** 更新包不含它们，不需要重新运行setup或下载模型。
3. 在ESP-IDF终端（或能正常运行既有程序的终端）执行：

```bat
cd /d D:\NOMI-ASR-debug\pc
start_control.cmd COM3
```

程序启动应显示`PC语音控制0.4.1`，按Enter开始。旧`start.cmd COM3`保留纯转录模式，不触发表情。如果实际工作目录已在pc内，不要输入`pc\start_control.cmd`。

没有旧安装的用户需先完成0.4.0固件/依赖/模型步骤，见[USB中文转录说明](USB_CHINESE_TRANSCRIPTION.md)；本更新包不含固件。不要误刷回0.3.0 commands版，也不要为本次更新擦除Flash或改原厂备份。

## 实际怎么说

先说“**小米同学**”或“**你好小米同学**”，等最终识别结果、设备确认并观察Listening，再单独说表情短语：

| 最终识别短语 | 串口请求 | 预期屏幕 |
| --- | --- | --- |
| 小米同学 / 你好小米同学 | listening | Listening，开放20秒指令窗口 |
| 开心一点 | happy | 开心 |
| 难过一点 | sad | 难过 |
| 眨一下眼 | blink | 眨眼 |
| 好奇一点 | curious | 好奇 |
| 思考一下 | thinking | 思考 |
| 认真听讲 | listening | 聆听 |
| 说话表情 | speaking | 说话动画，不播放声音 |
| 回到待机 / 休息一下 | idle | 待机，结束会话 |

只接受完整短语；“小爱同学”“小明同学”“小米同学开心一点”“不要开心一点”“他说开心一点”等不匹配，不擅自纠错执行。去除的是ASR标点、空格及全角形式，不删除否定词或任意前后缀。临时结果永不触发动作，停止时解码器补出的最终文本也仅显示，不执行。

只有接受到唤醒/表情指令才续期20秒；无关讲话不延长。20秒内以收到的**最终结果**判断，讲话开始于窗口内但最终结果已超时的指令不执行。短时间相同最终结果1.2秒内去重。当前设计为分两句话，不解析长句中的嵌入命令。

固件原有表情TTL=5秒。电脑在激活后约每2秒续发listening维持聆听；普通表情后先留约5秒展示，再恢复Listening。续发只维护屏幕，不延长20秒会话；终端标注“维持聆听窗口”。超时发送idle；设备自带TTL也是断连后的兜底，不增加固件状态。

## 如何判断接受和执行

- `[临时]` / `[最终]`：真实本地ASR结果，仍可能错字。
- `[接受]` / `[忽略]`：最终文本是否通过明确词表、唤醒和超时门控，以及原因。
- `[发送] happy ... 等待设备确认`：串口已请求，尚不能宣称成功。
- `[设备确认] 已接受 happy（请观察实际屏幕效果）`：已收到0.4.0固件的`nomi: Command accepted: happy (5s TTL)`回执。**这是设备接受指令，不是摄像头确认渲染完成或实体效果通过。** 必须看脸核对。
- `[异常]`：回执缺失超过1.5秒、不一致、指令积压超过1秒、队列满、串口短写或原有音频异常时停止，不用“发送成功”代替回执。

兼容旧固件的回执无独立命令ID，电脑仅允许一个指令等待确认；不同时开其它串口软件，不自动重发未确认动作。IDF日志可能在字符间插入完整PCM帧；接收线程把非PCM日志片段重组并匹配回执，音频仍须完整校验、连续序号，不能拼接损坏音频。

Ctrl+C/异常退出时，在已经发送过控制指令的情况下请求idle，再停止采音；退出阶段不继续等待回执，明确标记“已发送待机请求；退出阶段未等待设备回执”。若物理断线无法送达idle，固件原TTL约5秒后回退；这仍需实机断线测试。所有串口写入（心跳/表情/关闭）由同一个接收线程串行执行，不与ASR线程竞争写入。

## 模式与恢复

- `start_control.cmd COM3`：新语音控制模式。
- `start.cmd COM3`：保留纯转录模式，若需要先排查识别可直接用它。
- 默认仍使用原21MB中文模型、板载MIC1、2线程；可沿用`--mic 2`、`--threads 4`。`--wake-name "小诺同学"`可在PC模式显式配置新名称，同时接受“你好+该名称”，无需训练/刷机；必须能被当前ASR准确转录。
- `model.lock.json`和requirements不变；Windows识别本地运行、无API Key，不升级模型来掩盖控制错误。
- 屏幕底部蓝点仍只代表USB音频传送，不是新唤醒指示灯；以Listening/表情和终端控制状态共同验证。

## 验收与限制

1. 未唤醒说“开心一点”：应显示最终中文和“尚未唤醒”，脸不变。说近似激活名不应唤醒。
2. “小米同学”后观察listening回执和实际脸；逐一说上表短语，核对实际最终文字、接受原因、串口请求、回执、屏幕这五层，区分ASR错字和控制错误。
3. 普通表情展示后回Listening，20秒无有效指令回idle；无关讲话不能续期；“休息一下”后直接说表情应无效。
4. 临时结果中出现指令但最终句不同不得执行；“不要开心一点”等负样本不执行。每种指令至少重复5次，激活20次，记录误执行/漏识别，不能编造通过率。
5. Ctrl+C、拔线、设备重启、COM占用、丢帧和回执超时有明确错误/安全回退。重新启动不能执行上一轮积压指令。
6. 继续运行30分钟检查采音帧、队列、响应延迟和显示。当前只具备已有0.4.0短时硬件链路证据，**本次完整语音控制、回执重组/时序、异常回退与30分钟稳定性仍待用户实机验收**。

本次自动化软件测试覆盖确定性门控、回执/取消及与PCM交错的日志，不代替真实声音或真实屏幕验证。源码、测试、PC更新包与交接见对应分支，不创建PR、不合并main。
