# 0.4.2：编号回执与设备端聆听会话修复

## 本次日志确认了什么

用户0.4.1两次退出均为PC主动报`设备未在1.5秒内确认 listening`，对应后台每2秒发送的“维持聆听窗口”命令。第二次退出发生于新唤醒词的临时结果阶段，尚未提交重复唤醒；第一段在一个未匹配的眨眼短语之后超时。日志不支持“重复唤醒直接造成崩溃”的结论，也没有足够证据断言ESP32重启或普通回执具体在哪个环节丢失。

已经具备实际唤醒、happy/sad/blink、休息idle的用户反馈/接受回执，短时音频正常；这不代表全部异常/长时验收通过。不提交用户原始对话或完整日志。

0.4.1依赖ESP_LOG逐字符输出的普通接受日志；PCM完整帧可能在字符间插入，而且这些日志没有会话/指令编号。0.4.2取消对此类日志的控制依赖，并去掉每2秒刷Listening的控制流量，不以加长超时或伪造确认掩盖问题。

## 需要同时更新固件和PC

这次需要**固件0.4.2 usb_asr + PC0.4.2**，不能只换电脑程序。原模型、依赖、原厂备份不变，不需重新setup或下载模型，不擦除整片Flash。

1. Ctrl+C退出程序并关闭占用COM3的软件；保留原`D:\NOMI-ASR-debug\pc\.venv`和`models`。
2. 将完整0.4.2 ZIP解压到新目录，例如`D:\NOMI-042`，确认flash_args直接在此目录。ESP-IDF5.5.4终端执行：

```bat
cd /d D:\NOMI-042
python -m esptool --chip esp32s3 --port COM3 --baud 460800 write_flash "@flash_args"
```

3. 将ZIP中的pc文件夹合并复制到原`D:\NOMI-ASR-debug`，覆盖同名程序文件，保留原venv/models；不要删除整个原pc文件夹。然后执行：

```bat
cd /d D:\NOMI-ASR-debug\pc
start_control.cmd COM3
```

看到PC0.4.2，按Enter后应出现“0.4.2编号回执协议就绪”。若提示需要配套0.4.2固件，说明新电脑程序未收到新协议握手，不继续控制。不同时开miniterm。首次安装者才需要setup.cmd，纯转录start.cmd模式保留。

## 行为

- “小米同学”/“你好小米同学”：首次进入Listening，开放20秒会话。
- 已激活时再次说名称：仅发送`extend`续期20秒，**不重置脸、不打断尚在展示的表情**。
- 普通表情显示约5秒后，由固件自动恢复Listening；20秒无有效指令回待机。电脑不再每2秒发送Listening，麦克风的0.4秒心跳仍保留。
- “休息一下”/“回到待机”：立即结束会话回idle。程序结束、USB会话失效时固件也撤销远端会话并回idle；断线时序需实测。
- 只用最终识别结果。临时/停止后补出的结果不执行；未唤醒、否定/长句/近似名不做模糊匹配。

| 明确短语 | 表情/动作 |
| --- | --- |
| 开心一点 / 开心一下 | happy |
| 难过一点 / 难过一下 | sad |
| 眨一下眼 / 眨眼一下 | blink |
| 好奇一点 | curious |
| 思考一下 | thinking |
| 认真听讲 | listening |
| 说话表情 | speaking动画，无声音 |
| 休息一下 / 回到待机 | idle并结束会话 |

依然需要Windows本地ASR，不是ESP32独立中文识别；不接LLM/TTS/云服务、不保存录音/转录。蓝点仍表示音频传送，不代表唤醒成功；以终端最终文字、编号回执和实际脸核对。`--wake-name`仍可配置PC名称，须被ASR准确转录。

## 新确认链路

PC单线程串口写入`ctl <token_hex> <seq_hex> <action>`。token是当前USB音频会话随机值；probe序号0握手，随后按序递增，动作含八种脸与extend。固件检查当前采音心跳租约和明确动作，执行后返回：

```text
@NOMI_ACK1 <token> <seq> <action> <status> <hash>
```

hash为FNV1a32：同PCM校验算法，channel参数0，payload为ASCII`action + 空格 + status`。状态OK/STALE/INVALID/ASLEEP。回执为有前后换行的完整帧，经有限队列交给采音任务，单次USB driver write发出；主显示任务不阻塞写串口。ACK与PCM均整帧写入，TX缓冲由1024增至4096字节，避免同旧VFS逐字符日志竞争。

固件缓存同会话最近序号/动作/结果；重复请求只回原结果，不重复眨眼、不续期旧请求。旧序号/冲突动作拒绝，新token清理旧会话。PC不自动重发未确认动作；旧token/旧序号回执不能确认新指令，校验错误或不一致/超时仍明确停止。普通ESP_LOG文本不再有确认权限，不能误报“已执行”。回执说明应用接受，不证明屏幕物理渲染已验证。

聆听状态由独立RemoteControl管理，不把逻辑放入FaceModel。激活/指令建立20秒期限，普通表情有5秒展示期限，随后UI任务按期限设置Listening；重复唤醒只更新会话期限。结束/到期/心跳租约失效回idle，不保存对话或音频。

## 复测重点

1. 唤醒后反复叫名称：已激活时只看到extend及同编号OK，不应出现每2秒维持Listening的发送。
2. happy/sad展示期间再叫名称：续期，不立即打断；展示结束再Listening。
3. 两种眨眼短语均准确识别后可执行；普通聊天、否定、近似激活名不应执行。
4. 最后一条有效指令后安静超过20秒，实际回idle；休息后直接说表情无效。
5. 退出、拔线、重新连接后无旧会话/旧回执误确认；新会话probe #0。程序/设备重启和30分钟稳定性需实机测试。

自动化涵盖缺失/旧/错/损坏ACK、重复序号幂等、重复唤醒只续期、无周期控制、到期/断线清理和原采音/表情回归。软件/编译通过不等于这次实体修复已验收。恢复仍见[HARDWARE_H1](HARDWARE_H1.md)，原备份不动。
