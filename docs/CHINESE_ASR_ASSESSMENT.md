# 中文实时转录重新评估（2026-11-15）

## 最新需求及实机反馈

用户烧录0.3.0后观察底部绿点，但重复说“小米同学”没有进入Listening或变蓝。用户明确暂停继续扩展动作，要求先观察**任意讲话的真实中文转录**，而非已配置指令的中文名称。当前未取得本次开机/推理串口日志，不能据此判断麦克风坏了、模型具体听成哪个词，或单纯阈值问题。

用户此前要求“必须脱离电脑，仅在ESP32上识别”。本次选择“任意讲话的完整中文转录，先重新评估实现方案”，没有授权改为电脑/云端识别，也没有授权购买硬件或模型服务。因此本次仅评估和记录，不修改固件、不上传音频、不下载大模型、不调用收费服务。

## 核查结论

1. 现有Waveshare ESP32-S3-Touch-LCD-1.85B：用户实测16MB Flash、8MB PSRAM。已有H2采音/AFE短时运行证据；0.3.0通用指令模型的目标词激活**尚未实机验证通过**。绿点表示初始化就绪，不等于准确识别通过。
2. 当前ESP-SR固定版本2.0.1（upstream v2.0.0 / `1c0503e7e2dc5e1ecb2fd3da0a5d7e51e3574842`）的MultiNet是有限词表指令识别；固定版本文档说明最多200条。最新仓库快照`bb552f1a559396a17681299cb3e199a0f1a4520a` README写300条，仍是指令识别；升级版本不会因此变成任意讲话转录。
3. `get_results()`的指令ID/候选分数，以及将该ID查表打印成“小米同学”，**不等于任意讲话的真实转录**。不能把程序预设句子作为用户的实际讲话打印，也不能把VAD/音量变化当文字识别。
4. ESP32可以通过串口输出UTF-8中文。终端使用UTF-8即可；显示编码无法补上缺少的ASR模型。当前不是更换串口助手或再烧一次同样固件就能解决的功能差异。
5. 未核实到适合当前8MB PSRAM、可在本板持续实时运行并交付的通用中文ASR方案。作为资源量级参考，whisper.cpp上游README的未量化tiny模型约75MiB，运行内存约273MB，明显超出本板；这不是对所有可能ASR方案的绝对不可能证明，也不是实测本板跑过Whisper。不同量化/模型/上下文有不同资源需求，不能据单个参考数字保证其它模型可用或不可用。

| ESP32采音，经USB送Windows，Windows本地流式ASR | 可实现，效果/延迟需测试 | 否 | 否 | 不上云，但需明确同意临时使用电脑计算 |

## 建议的临时调试设计（待用户选择，不是已实现）

若用户接受本阶段借助Windows本地计算，先只验证真实转录，暂停动作执行。保留最终脱离电脑的需求作为下一次硬件/模型决策，不把临时方案冒充最终方案。

```text
板载ES7210麦克风 → ESP32 16kHz/PCM16单声道
    → 有帧边界/类型/序号/长度/校验的USB数据流
    → Windows接收与中文流式ASR
    → 终端UTF-8显示“临时结果 / 最终结果 / 无识别结果 / 音频异常”
```

- 必须使用**ESP32板载麦克风**的音频，不用电脑麦克风替代。首先核对采样率、幅度、声道、削波、丢包与实时积压，再评估ASR准确率。
- 默认不落盘录音或完整转录。用户主动启动/停止采集；USB断开、应用退出、缓冲积压时停止或明确报错，不悄悄丢帧后继续显示假正常。先不触发表情、不接LLM/TTS。
- 候选引擎：sherpa-onnx中文流式Zipformer/Paraformer。上游提供Windows及中文流式模型支持；具体模型、版本、许可、SHA256、下载体积、CPU占用与端到端延迟必须在实施时固定并测试。目前未下载/运行，不声称已经验证。
- 音频32,000字节/秒（16kHz×单声道×16bit）。真正UART的115200/8N1有效载荷理论上约11,520字节/秒，不足传输此原始PCM；本板USB Serial/JTAG是原生USB虚拟串口，不能把界面115200参数当作实际USB吞吐上限，也不能只改波特率就宣称吞吐够用。需实测序号/吞吐/积压。
- 不把原始二进制PCM与无帧边界日志混在同一流直接交给miniterm。由一个配套程序独占COM端口、解帧并显示中文；它运行时不能让另一个miniterm同时打开COM3。
- 纯中文文本监视可用 `python -m serial.tools.miniterm COM3 115200 --eol CRLF --encoding UTF-8`；这条命令仅设置显示编码，**不会为现有0.3.0固件增加转录能力**。
- “实时”需区分讲话中的临时假设和停顿后的最终句子；临时结果可能修改，不承诺逐字零延迟或100%准确。当前只能设计目标，不能提前宣称达到具体延迟。

## 进入开发前的决策

需要用户明确是否允许临时使用Windows本地ASR。若不允许，进一步确认是否愿意改变最终计算硬件；维持仅当前ESP32则本次未找到可交付方案。任何路径确定前不让用户重复烧录，也不再要求用说唤醒词的方式替代转录验证。
