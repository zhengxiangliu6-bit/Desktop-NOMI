# 0.5.1：板载扬声器固定回应“好的”

## 范围和当前证据

用户反馈0.4.2最新版本效果很好，作为当前可用基线保留；这不是所有异常和30分钟稳定性已通过的证明。本次最新需求授权新增固定语音反馈：接受有效指令后，从**设备自带扬声器**说“好的”。不扩展自由对话、云端、动态TTS、记忆或舵机。

实现为固件内置固定合成PCM资源，不采集/提交用户录音，不克隆真人声音。运行时不需要TTS服务、下载新语音模型或支付调用费。Windows本地ASR模型/依赖不变，设备仍需要Windows程序完成识别。

官方板型固定提交`5a98b8da1948340c07032a408ac0d93c47ca558f`已核对：06_mic_test的BSP使用ES8311 DAC、PA GPIO9（默认不反转，即高电平启用），I2S1 MCLK2/BCLK48/WS38/DOUT47/DIN39，I2C SDA11/SCL10。沿用本项目16kHz/16bit/stereo共用时钟，不用其他板型配置，不重开24kHz模式影响采音。

## 预期行为

- 第一次说“小米同学”或“你好小米同学”：Listening并回应一次“好的”。
- 明确表情指令被接受：切换对应表情并回应一次。说“休息一下”/“回到待机”：idle并回应一次。
- 已激活时再次叫名称：仅extend续期，不重复说“好的”、不打断表情。
- 20秒自动到期、后台状态维护、握手、无关/未唤醒/被拒绝句子、重复编号、退出清理：不播放。
- 终端仍分开显示中文、接受/忽略、编号回执；另有`[回应]`START/DONE/ERROR/BUSY和`[播放保护]`暂停/恢复。数字DONE代表输出流程与保护期完成，**不代表助手已听到实体扬声器发声**。

## 播放与防回灌

固定素材534.0625ms、16kHz/PCM16LE/mono，17,090字节。开发阶段由固定文字“好的。”离线神经合成（MeloTTS中文公开女声/sherpa-onnx2.0.1 CPU/speaker0/speed1.0、FFmpeg7.1.5归一化），不会在用户电脑安装此生成器。SHA256及生成来源见`firmware/components/nomi_audio/assets/okay.json`和NOTICE。仅此合成构建资源随固件交付，用户麦克风音频仍不保存、不打包。模型卡标注MIT，随包提供原许可文本。神经合成也需要用户试听，不承诺实际扬声器音色已经满意。

ES8311输出音量设60/100（Codec软件音量，**不是响度/功率百分比**），低于官方示例80；数字素材峰值13392/32768。实际响度、失真、爆音及音质均需实机听测，不能凭软件音量承诺音量合适。PA只在明确播放请求时GPIO9高；输出结束后拉低并DAC静音。断线、关闭、异常、初始化/写入失败均在清理路径关闭功放。

采音任务独占播放操作，分320采样/20ms块把mono复制到左右声道，保持16kHz共享时钟，I2S写等待上限20ms。没有在UI任务中延迟或阻塞播放。继续读取RX，防止DMA溢出；不缓存任意长语音或排长队；若已有回应未结束则报告BUSY、不插播。控制重复编号无副作用，不再次触发音频。

这是基础**半双工反馈**，不是AEC：播放约0.5秒后保留100ms DMA排空和300ms余音保护，总约0.94秒；期间继续传连续音频帧，但实际麦克风数据被明确标记并替换为零。Windows在保护开始/结束重置ASR，保护帧完全不送模型，防止自己的回应被显示成输入或触发新动作。**这段时间用户说的话也会被忽略；听完“好的”并看到“恢复识别”后再说下一条。** 不支持边播放边打断。

## 成对升级到0.5.0

必须**固件0.5.0 + PC0.5.0**，原模型/venv保留，无需setup或重下模型。新PC握手携带明确播放意图字段，旧0.4.2不支持会拒绝/超时；不要混用。

1. Ctrl+C结束旧程序，关闭COM3软件。新完整ZIP解压到例如`D:\NOMI-050`，确认flash_args直接在该目录。
2. ESP-IDF5.5.4终端：

```bat
cd /d D:\NOMI-050
python -m esptool --chip esp32s3 --port COM3 --baud 460800 write_flash "@flash_args"
```

3. 将新ZIP的pc文件夹合并到原`D:\NOMI-ASR-debug`，覆盖程序，保留已有`.venv`和`models`，不删除整个pc目录。然后：

```bat
cd /d D:\NOMI-ASR-debug\pc
start_control.cmd COM3
```

看到PC0.5.0，按Enter后应显示“0.5.0编号回执及固定回应协议就绪”。先只测一次唤醒并听扬声器；等恢复识别，再说“开心一点”。不整片擦除，不覆盖原厂备份。需要回退可使用已保留的0.4.2完整固件/配套PC包。

## 协议变化

控制命令`ctl token seq action spoken`，spoken=0/1。probe/extend/自动idle为0，明确接受的人声指令为1。ACK仍为带编号校验的NOMI_ACK1；设备只在新序号、成功Face效果且spoken=1时安排回应。缓存重复请求仅回原结果，不重复动作/播放，改变同编号的spoken字段拒绝。控制ACK表示接受动作，不保证物理播放成功。

新音频行：`@NOMI2 token seq channel flags hash base64_PCM`。flags bit0=播放/余音保护，仅0/1允许；hash=原FNV函数(token,seq,channel,flags单字节+640字节PCM)。flags纳入校验，不能篡改成正常帧。PC解析也保留旧NOMI1以兼容离线样本/纯转录诊断，但带声音控制必须配套升级。

回应事件`@NOMI_SAY1 token seq START|DONE|ERROR|BUSY hash`，FNV的channel参数0、payload为事件ASCII。它与控制ACK、音频分开，不作为新的控制输入。ERROR报告后停止；设备清理时功放低/静音。音频/ACK/回应事件均由同一采音任务完整driver write发出，原序号与租约机制保留。

## 验证状态与实机验收

本地软件：固定PCM被现有真实ASR解码为“好的”；帧/标志校验、ASR保护重置和不喂入、只为人声指令回应、重复请求不重播、播放/排空/尾音时序与取消、原表情/会话回归均可自动验证。**这些不能证明板载扬声器已经播放过。**

实体待测：

1. 一次唤醒/每个有效表情/明确休息各仅回应一次，听到确为“好的”，音量和音质可接受；相近名/无关词不回应。
2. 重复叫名仅extend，不连播；自动20秒idle安静；原表情和待机恢复不变。
3. 回应期间终端暂停识别，回应不应作为用户文本出现；结束后恢复。用户主动在保护期讲话被忽略是已知限制。
4. 连续10次“等待回应结束→下一条”不积压、不DMA溢出/帧丢失；停止/拔线/播放异常后功放关断，不能持续响或自触发。
5. 继续检查真实USB吞吐、回应期间帧连续性、30分钟稳定性和栈/内存。若无声，保留回应START/DONE/ERROR/BUSY及相关设备错误输出；不要据DONE直接写“扬声器验收通过”。
